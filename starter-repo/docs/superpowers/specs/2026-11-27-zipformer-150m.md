# Zipformer 150M ONNX for local and Railway images

## Goal
Use the selected Vietnamese Zipformer 150M INT8 model for speech recognition in both the API image used by Railway and the local Streamlit demo image.

## Approaches
- Keep 30M: smallest runtime, lower accuracy on most newer Vietnamese benchmarks.
- Replace with 150M INT8 files: better reported accuracy, adds about 124 MB encoder artifact and requires memory smoke testing. Recommended because the user selected this model and Railway can build the files into the image.
- Ship the full Hugging Face repository: rejected because it includes unused FP32 and checkpoint artifacts and makes the image unnecessarily large.

## Design
Pin the Hugging Face revision `8c3d474d3d74cb247f4b8c7b0f8b48598ac8c1c6`. During the Docker build, fetch only the INT8 encoder and joiner, decoder, and token list; map them to the filenames the existing ONNX loader expects. Apply the same model selection to `Dockerfile.api` and `Dockerfile` so Railway and the local container behave consistently. Preserve the loader unless real graph inspection or WAV inference proves it incompatible. Document the model revision, license, artifacts, and what still needs deployment-level verification. Do not deploy to Railway in this change.

## Validation
Inspect ONNX graph names/metadata and load all three sessions; transcribe the bundled WAV samples; run the existing unit suite and Docker build/resource test if the environment supports them. Report any unavailable verification explicitly. The linked model card declares `cc-by-nc-nd-4.0`; deployment/use rights must follow that license.
